Step 1

Open a pack

A "pack" = one expense report for one trip or period.

Pack → Report. A pack is what you're putting together — receipts, documents, per-diem. When you submit it, the pack becomes a report and accounting takes over: they approve an amount or send it back. One pack open at a time.

No confirmation needed. A single receipt — photo or file — is read and saved straight away, and you see every field it recognised — so a wrong one is obvious immediately. Keep sending photos; each becomes its own line.

An expense you only describe in words is saved straight away too. If the bot took it for one with a document behind it and no file was there, it says so under the read-out: “ℹ️ No document is attached to this line — send it if you have one.”

🧾 Send the real document, not just the payment slip. For a hotel that's the invoice or folio (guest name, check-in and check-out); for a flight the ticket or boarding pass (route and date). A bank confirmation proves money moved but not who stayed or flew when — the bot points this out before you submit, and you can still send it as it is.
⚠️ If a save ever fails, the bot says so — and why. “⚠️ That receipt wasn't saved, and nothing half-saved was left behind. Why: writing the file did not work.” The reason is one of report #42 is submitted, writing the file did not work, something went wrong on my side while saving it, or the first line of the failed step's own answer. What to do next depends on it:
• the report is already with accounting: “Report #42 is submitted — it can't take new lines. Reopen it from /myreports, or start a new report with /newpack, then add this expense again.”
• you had sent a photo or PDF: “Send the photo or PDF again and I'll read it from scratch. If the second try fails the same way, /feedback puts it in front of a person instead of another retry.”
• you had described it in words: “Tell me about it again and I'll add it. If the second try fails the same way, /feedback puts it in front of a person instead of another retry.”
If a multi-page document was being collected, the next step is followed by “📚 Your 3 page(s) are still here — this did not touch them. Send the next page, or tap Document complete.”, with ✅ Document complete · 🚫 Cancel on top.
Under it are the pack buttons and 💬 Leave feedback — the second step is one tap, not a command to remember.

When you asked the bot to attach a document to a line, or to file a Travel Request, and writing that file fails, the bot answers in its own words — and under that answer, always, comes “Still holding your photo.” with 🚫 Discard it (it says “photo” for a PDF too). The file is kept: tell the bot again what it is, or discard it. What you never get is a silent card with the receipt missing from the report.

Step 2 · a file on hold

“Is it the document for this line?”

Sometimes the bot keeps a file back — a save failed and it kept the copy, or it asked you something about it first. It never quietly pins that file onto a different line.

Say it is holding a hotel invoice, and you now describe a taxi ride in words. The file was not read for the taxi, so the bot asks:

Bot: 📎 I'm still holding the PDF I read as Motel One Zurich · 1136.00 CHF.
Is it the document for Careem · 50.00 AED?
📎 Yes — attach it to this line
➕ No — different expense, save without it

For a proof document the second button is ➕ No — a different document, and then nothing is filed: “Nothing filed for … — send that document itself and I'll file it.”

If more than one line wants the file and it matches none of them:

Bot: 📎 I'm still holding the PDF I read as Motel One Zurich · 1136.00 CHF.
It was asked for by more than one line, and it matches none of them. Which one is it the document for?
📎 Attach it to Careem · 50.00 AED
📎 Attach it to Talabat · 85.00 AED
✋ None of these — keep it

After your tap the question is rewritten to say what happened: → attached to Careem · 50.00 AED or → kept. If the save after Yes was refused or failed, it reads → not attached, the next message says why — for a failed write, “⚠ That one wasn't saved — writing the file did not work. I still have what you sent, so nothing was lost. Send it again, or tell me what it is and I'll try with the copy I'm holding.” — and the same question is shown again. The line and the file are both kept: Yes tries again, No saves the line without the file. Answer No in the first place and the line is saved without the document; the file stays with the bot, named, with a 🚫 Discard it button.

🕓 An attach button never sends the file to a different line. Yes and Attach it to … each name one line. A button on an older copy of the question either attaches the file to exactly the line it names, or leaves the file where it is — never to another line. Tap the newest copy to be sure what you are answering. When an older button is turned down, its message changes to — this question was answered or replaced — and the current question is shown again. If the line that button named can no longer take a file, it reads — not attached: that line can no longer take a file —; and when nothing is left to ask about, the bot says “Not attached — that line can no longer take a file.” followed by “📎 Still holding … — tell me what it is and I'll file it.” with 🚫 Discard it.
📷 A photo held from earlier is asked about too. If the bot answered your photo with a question — tell me what it is, or who you met at a business lunch — and you reply by describing the expense, it does not attach the photo on its own; it asks, and one tap settles it:
“📎 I'm still holding the photo you sent. Is it the document for Careem · 50.00 AED?” — 📎 Yes — attach it to this line / ➕ No — different expense, save without it.
If several lines want it: “It was asked for by more than one line. Which one is it the document for?” When the bot reads the expense straight from the photo you have just sent, nothing is asked. The extra tap is the price of never pinning a file to the wrong line; it may be removed later, but for now it is there.
👆 Only a tap answers this question. Typing yes or no while it is on screen attaches nothing and settles nothing — the bot reads it as an ordinary message. The one exception is a value the bot itself asked you for: tap ✏️ Change → Amount and type the number, and the number is taken.
🔗 The same goes when you ask in words — “attach it to my Careem line” — and the held file was read as something else: “That doesn't match Careem · 50.00 AED. Use it for Careem · 50.00 AED anyway?” with 📎 Yes — use it there and ✋ No — keep it for now.
Step 2 · a file on hold

What happens to a file the bot is holding

Where it stops and asks you — and, for now, where the file can still go without a word.

These stop, name the file, and let you decide:

📚
Tap “Multi-page document” “📎 I'm still holding the PDF I read as Motel One Zurich · 1136.00 CHF. A multi-page document would replace it. Tell me what it is so I can file it first — or discard it and start the document.” Buttons: 🗑 Discard it and start, and — only when the held file is a photo the bot has not read yet — 📚 Use it as page 1.
📄
“📚 Multi-page — I'll send the rest” on a PDF If the bot took a PDF for page 1 of a longer document, this button refuses and says why: “📎 I'm still holding the PDF … — it's a PDF, so it can't be page 1, and a multi-page document would replace it.” with 🗑 Discard it and start. The PDF stays; send the whole document as one PDF instead.
✅
Tap “Document complete” “📎 I'm still holding the PDF I read as Motel One Zurich · 1136.00 CHF. Your 3 page(s) are kept either way. What should I do with it?” Three buttons:
• 📄 File it as its own expense, then finish — a file the bot has already read becomes its own line, “✅ Added: Motel One Zurich · 1136.00 CHF (PDF attached).”, and your pages are assembled straight after, no second tap. A file not read yet is read first — “📄 Reading the photo you sent as its own expense…” — the pages stay, and then “📚 Your 3 page(s) are still here — tap Document complete when ready.” If filing fails: “⚠️ Couldn't file the PDF — {reason}. Still holding it; your 3 page(s) are kept.” and the same three buttons (“photo” for a photo).
• 🗑 Discard it, keep my pages — “🗑 Discarded the PDF I read as Motel One Zurich · 1136.00 CHF. Your 3 page(s) are still here.” with ✅ Document complete · 🚫 Cancel.
• ✅ Document complete — the same screen again until the file is settled.
📂
Switch to another pack 📂 Continue in /myreports moves you, and the file comes along: “📎 Still holding … — tell me what it is and I'll file it here, or discard it.” with 🚫 Discard it.
🚫
Type /cancel With a card on screen, it drops the card, not the held file: “📎 Still holding … — tell me what it is and I'll file it, or tap Discard.” with 🚫 Discard the held file. With nothing else pending, /cancel is the discard — and names what went: “🚫 Dropped the PDF I read as Motel One Zurich · 1136.00 CHF. Nothing was saved.”
🔑 Discard buttons are tied to what they discard. 🚫 Discard it, 🚫 Discard the held file, 🚫 Cancel on a receipt card, 🗑 Discard it and start and 🗑 Discard it, keep my pages each carry their own file or card. Tapped on an older message after that file or card has changed, the button touches nothing and says so in a pop-up — — that card is no longer active —, — that file is no longer held — or — nothing is held —. Sometimes the bot also puts what is current at the bottom of the chat; tap there. Not tied: the 🚫 Cancel under “📄 Page N received…” and the other screens of a document being collected — it cancels whichever collection is running now.
⚠️ Where a held file can still disappear — being fixed.
• Sending the next photo or file while one is held and no card is on screen replaces the held one: “↻ Replaced your previous photo with this … — I only hold one at a time.” It does not say which file went, and calls it a photo even when it was a PDF.
• Submitting the pack — /compile, 📤 Submit for review, submit anyway — lets go of the held file without a word.
• Deleting the pack does the same.
• Tapping 📚 Multi-page document while a document is being collected — or an old 📚 Multi-page — I'll send the rest — starts the collection over without a word; the pages collected so far drop out.
• An old 🚫 Cancel from an earlier document, tapped while a new one is being collected, cancels the new one and throws its pages away: “🚫 Document cancelled — nothing was added.”
Until this is fixed: when the bot says it is still holding a document you need, tell it what the document is before you send the next one, submit, or delete the pack; and while collecting pages, finish with ✅ Document complete rather than starting again.

Step 4 · continued

Wrong amount or currency

A dirham receipt read as another currency, or a figure with a comma in it — both are one tap and one message.

On a saved line, tap ✏️ Fix (or its number in /showpack), then Currency:

Bot: Send the new currency — a code like USD, or a sign like € or Ð.
You: Ð
Bot: ✅ Added:
Vendor: Careem
Amount: 125.00 AED
Type:   Transportation
Date:   2026-05-12
Anything else wrong?

Currency takes a code (USD, eur), a sign (€, $, £, Ð) or a word (dirhams, UAE dirhams, euros). A word it does not know gets I don't know “…” as a currency. Send a code like USD or EUR, or a sign like € or Ð. An amount sent with it — 125 USD — gets Send only the currency, without an amount — e.g. USD, € or Ð. Either way nothing changes and the bot keeps waiting for the currency. The figure itself stays as it is — only the currency changes.

🔢 How a typed amount is read — in Amount here, in ✏️ Change → Amount on a multi-page card, and in the accountant's /approve and ✏️ Other amount:
• 6117,37 is 6117.37 — a comma before one or two digits is the decimal point;
• 6,117.37, 6.117,37 and 6 117,37 are all 6117.37 — with both marks, the last one is the decimal point;
• 1,200 or 1.200 could be either (some currencies use three decimals), so the bot asks instead of guessing: “1,200” could be 1200 or 1.2 — I didn't guess. Send it again as 1200 or 1.2.
• not a number at all: That doesn't look like a number. Send the amount again, e.g. 1250.50. (/approve answers differently: I couldn't read the amount “…”. and shows how to write the command.)
• a different currency next to the number is not converted, and nothing is changed. On an AED line, Amount → 150 USD: “150 USD” is in USD, but this line is in AED. I didn't convert it, and nothing was changed. Send the amount in AED. If AED itself is wrong, tap ← Leave it above, then Currency. The line's own currency is fine — 150 AED, 150 dirhams. The currency is checked first, so 1,200 eur is refused for the currency, not asked about. On a multi-page card the words are “… but this receipt is in …”; for the accountant “… but the approved amount is in AED …” — after Report #54 was not approved. on /approve, and followed by Or 'cancel'. on Other amount.
💱 The AED total follows. Change the amount or the currency and the line's AED value is worked out again at today's rate — the report total moves with it. If the rate cannot be fetched and the line is switching to a currency other than AED, the bot changes nothing: “I couldn't get today's exchange rate, so nothing was changed. Try again in a minute.” A new amount in the line's own currency does not wait for it — the rate the line was booked at is used.

After approval

What approval sends — and how to take a report back

Approving is one tap for the accountant. Here is everything it sets off.

💬
You — a message in Telegram “Your report #42 is approved. Amount approved for reimbursement: 1240.00 AED.” That is the figure the accountant approved — lower than your claim if they cut something. The other accountants get a line saying who approved it and for how much. The employee gets no email.
📧
The accountant who approved it — an email with the PDF Sent to the address that accountant set with /myemail. Subject: “Expense report #42 approved — 1,240.00 AED — Anna Smith”. The body lists the report and its name, Employee, On behalf (only when filled in), Submitted total, Approved amount, a Difference line when the two are not the same, Approved by and Approved at. Attached: expense_report_42.pdf — the report rebuilt at that moment, with a green APPROVED FOR REIMBURSEMENT: 1,240.00 AED box on its cover. A report too big for mail goes without the PDF, and the mail says so and asks for it in Telegram.
🔁
/resend 42 — when the mail did not go The approver sees the outcome under the approval: “📧 Emailed to …”, or “📧 Could not email it to …” ending in “Retry with /resend 42.”, or “📧 Not emailed — you have no address on file. Send /myemail you@company.com and then /resend 42.” /resend 42 mails the approved report again — to the address of whoever types it — and changes nothing about the report. On a report that is not approved it answers that there is nothing to email yet.
🔒 An approved report is frozen. Nothing in it can be edited — not by you, not by the accountant. To change it, it has to be taken back. ↩️ Reopen in /myreports does that — the buttons sit under the six most recent finished reports in the list, and a returned report takes one of those six places without getting a button. It asks first:
Bot: ↩️ Reopen report #42 «Zurich May 2026»?
The accountant approved it at 1240.00 AED on 2026-05-20T10:03.
Reopening takes it back so you can edit it. The accountant is told that you did, and nothing reaches them again until you submit it.

← Leave it
After Yes the pack is open again and is the one you are working on. An older report without a button can be reopened in words — “reopen report 42” — and then there is no confirmation button; accounting is told all the same. For an approved report, Reopen — the button or the words — is the only way back: the accountant cannot return an approved report. For accountants

Reviewing reports

If you're an accountant, each submitted report arrives here as a PDF. Process it with these commands.

/pendingList all reports awaiting review
/report 54See report #54 — status + PDF
/approve 54Approve at the full submitted total
/approve 54 1200Approve a custom AED amount (e.g. after cutting items). 6117,37 is read as 6117.37. 1,200 is not guessed: the report is not approved, the bot names both readings, and you send the command again — /approve 54 1200. A number typed on its own is not taken as the answer; only ✏️ Other amount waits for one. Another currency — /approve 54 2563.20 eur — is refused, not converted: the approved amount is in AED
/return 54 …Send back for fixes with a note
/reply 54 …Message the employee
/status 54Quick status — who reviewed it, the note
/myemail you@…Where your approvals are emailed, as a PDF stamped with the approved amount. /myemail shows it, /myemail none stops it
/resend 54Email approved report #54 again, if the mail failed
⚠ Gap flags. /pending and /report mark lines backed only by a payment slip (e.g. a hotel charge with no invoice, a flight with no ticket) — so you can ask for the missing document before approving.
🔘 Buttons, not only commands. Every report arrives with ✅ Approve (showing the total, e.g. ✅ Approve 1,240.00), ✏️ Other amount and ↩️ Return under it. The last two wait for you to type — an amount, or the note the employee receives. Send a photo or a PDF instead (your own receipt, say) and the bot stops waiting and tells you what did not happen: the report was not returned, nothing was sent to the employee, the approved amount is unchanged. Whatever you type next is read normally, and the buttons are still there.
💡 The number is the report id from /pending. #54, 54 or report 54 all work. The employee is notified automatically on approve/return. Type /review in the bot for this list anytime.
